# Запуск и автоматизация

## Что должно быть поднято

1. **Ядро** — AI Freelance Copilot (обязательно; без него агент ничего не разберёт):

```bash
cd "D:/python projects/AI_Freelance_Copilot"
./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8800
```

Первые 5 заказов заливаются один раз: `python scripts/orders_ops.py ingest`
(команда идемпотентна).

2. **OpenClaw gateway** — работает как задача Windows с триггером «при входе в систему»
(создаётся при установке OpenClaw, отдельной настройки не требует):

```bash
openclaw gateway status      # Running + порт 18789
openclaw gateway restart     # если агент не виден в дашборде
```

## Сводка по заказам: по требованию, а не по расписанию

Новых заказов система сама не находит: единственный источник заказов в ядре — `manual`
(парсинг площадок не реализован, ТЗ §22). Пока компьютер выключен, заказов не возникает;
когда включён — их приносит человек. Поэтому сводка нужна в конце рабочей сессии,
когда ядро уже поднято и заказы разобраны:

```bash
cd "D:/python projects/openclaw-orders-agent"
python scripts/orders_ops.py summary      # → reports/daily-summary.md
```

### Что было и почему снято

30.10 в проекте была задача Windows `Orders Agent Summary (logon)` с триггером
«при входе в систему»: она запускала `scripts/daily_summary.cmd` → `summary`.
Смысл затеи был в том, что владелец выключает компьютер между сессиями и расписание
по часам срабатывает вхолостую.

02.11 автоматизация снята по решению владельца. Причины две, и вторая важнее первой:

1. сводке нужно живое ядро на `127.0.0.1:8800`, а при входе в систему его никто
   не поднимает: за всё время **0 успешных запусков из 10** записей в
   `reports/logon-summary.log`, последний код возврата задачи — 2;
2. у сводки нет источника новых данных. Заказы появляются только вручную, поэтому
   отчёту «по расписанию» нечего сообщать. Поднимать сервис при каждом входе ради
   пустого отчёта — лишний постоянно живущий процесс, а не автоматизация.

Разбор целиком — карточка DEF-021 в репозитории приёмки (`qa-llm-acceptance`);
журнал запусков оставлен там же как история.

`scripts/daily_summary.cmd` оставлен как ручная обёртка: запускает сводку и пишет
вывод в тот же журнал. Задачи Windows за ним больше нет.

### Cron OpenClaw (остаётся как часть сдачи)

Задача `0 8 * * *`, часовой пояс `Asia/Krasnoyarsk`, изолированная сессия, агент
`orders-operator` — это требование учебной сдачи проекта, поэтому она остаётся.
Новых данных она не даёт по той же причине: срабатывает, когда компьютер выключен.

```bash
openclaw cron list          # статус и последний запуск
openclaw cron runs <job-id> # история запусков
```

## Ручной запуск (для проверки и скриншотов)

```bash
cd "D:/python projects/openclaw-orders-agent"
python scripts/orders_ops.py health
python scripts/orders_ops.py ingest
python scripts/orders_ops.py triage --analyze --only-new
python scripts/orders_ops.py summary
python scripts/orders_ops.py test
```

Интерпретатор — `python`, не `python3`: на Windows имя python3 перехватывает заглушка
Microsoft Store, и скрипт не выполняется. Результат сводки — `reports/daily-summary.md`
с датой и временем формирования.
