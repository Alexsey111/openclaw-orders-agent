# Демо на 90 секунд: что показать и в каком порядке

Запись одним куском, без монтажа и без озвучки поверх — только экран и голос.
Цель: незнакомый человек за 90 секунд понимает, что было, что стало и чем проверено.

## Подготовка (до записи, в кадр не попадает)

```bash
# 1. ядро на отдельной базе прогона — двойной щелчок по scripts\run_live.cmd
#    или из PowerShell:  cd "D:\python projects\AI_Freelance_Copilot"; .\scripts\run_live.ps1
#    (в cmd.exe/PowerShell строки вида DATABASE_URL=... не работают — это синтаксис bash)
cd "D:/python projects/AI_Freelance_Copilot"

# 2. окно терминала — крупный шрифт, тёмный фон, ширина ~110 символов
cd "D:/python projects/openclaw-orders-agent"
python scripts/orders_ops.py health          # ядро живо, провайдер openai, модель gpt-4o-mini
```

Проверить до записи:

- в базе прогона ровно 20 заказов `fl-2411-001…020`; тестовые заказы от n8n из неё убраны
  (иначе в таблице 22 строки и числа 9/4/9 вместо 8/4/8);
- микрофон по умолчанию — «Микрофон (USB Audio)»: 04.11 замерено −22 dB средний уровень,
  −1 dB пик. Второй вход «Microphone (USB Audio and HID)» молчит (−75 dB) — если Game Bar
  возьмёт его, запишется тишина;
- в браузере открыт только README агента (вкладка на разделе «Прогон 20 заказов…»);
  README ядра — заготовкой в соседней вкладке, для ответов после записи, не в кадре;
- в `.env` ядра ключ есть, но в кадр он не попадает — `.env` не открывать;
- один прогон на записи стоит ~1,37 ₽, повторная запись — ещё столько же.

## Кадр 1 (0:00–0:15). Что было

Экран: README **репозитория агента** на GitHub — `Alexsey111/openclaw-orders-agent`, раздел
«Прогон 20 заказов на реальной модели» (27-я строка, один скролл от шапки). README ядра
в кадр не берём: 413 строк, это материал защиты на 10–12 минут, а не на 90 секунд.

Голос: «Разбор заказа вручную — восемь минут: минута на поиск, семь на оценку сил,
сроков и цены. Двадцать заказов — два часа сорок. Вот что получилось, если рутину
отдать агенту».

## Кадр 2 (0:15–1:00). Что делает система — прогон идёт вживую

Терминал:

```bash
python scripts/orders_ops.py --timeout 180 triage --analyze --limit 25
python scripts/orders_ops.py queue
```

Прогон 20 заказов идёт 42–48 секунд (замер 04.11: 48 с на команду целиком, 2,1 с на заказ,
максимум 4,1 с). Это не мёртвая пауза, а главное доказательство: модель работает на глазах,
без монтажа. Пока строки появляются, говорите — примерно 80 слов на 35–40 секунд:

> «Двадцать заказов, на каждый — один вызов модели. Пока идёт прогон, объясню, что происходит.
> Заказ кладётся рядом с профилем — профиль настоящий: тринадцать навыков, минимум пятьдесят
> тысяч, список «чего не беру». Модель отвечает строгим JSON: оценка, решение, причина,
> черновик отклика. Дальше в дело вступают правила ядра: бюджет ниже моего минимума — отказ;
> низкая уверенность — человеку; модель разошлась с расчётом по профилю — тоже человеку.
> Поэтому «восемь откликаться, четыре на проверку» — это не ответ модели, а решение системы
> поверх него».

Когда таблица появилась:

> «Вот результат: восемь — откликаться, четыре — на проверку, восемь — пропустить.
> Очередь проверки — четыре записи, у каждой причина».

Если не хочется долгой паузы — не сокращайте прогон, а сдвиньте команду в конец кадра:
сначала объяснение, потом запуск, и таблица появляется уже под конец рассказа. Сокращать
до `--limit 5` можно только для репетиции: в кадре числа перестанут совпадать с README.

Показать в таблице две строки: одну «откликаться» с оценкой, одну «на проверку» с причиной.

## Чего в кадре не делать

- Не открывать `.env`, настройки провайдера и личный кабинет.
- Не показывать файловый менеджер с чужими проектами — только терминал, README и отчёт.
- Не перезаписывать дубли: два дубля — два прогона, каждый по 1,37 ₽.
- Не обещать того, чего нет: отправка откликов не автоматизирована (ТЗ ядра §22),
  в кадре это говорить как ограничение, а не как «сделаю потом».
