# Оператор входящих заказов (OpenClaw-агент)

Агент разбирает входящие фриланс-заказы и показывает по каждому: **откликаться**, **на проверку**
или **пропустить** — с причиной и, где возможно, готовым черновиком отклика. Надстройка над ядром
[AI Freelance Copilot](https://github.com/Alexsey111/AI_Freelance_Copilot), а не замена ему:
оценки и решения считает ядро, агент оркеструет разбор и объясняет результат человеку.

## Зачем

Владелец разбирает заказы вручную: поиск и чтение ~1 мин, оценка своих возможностей, сроков и
цены — 5–10 мин (в среднем 7). Это ~8 минут на заказ. Агент снимает эту рутину: заливка заказов,
прогон через ядро, понятная сводка «что брать, что проверить, что пропустить», а по расписанию —
готовый отчёт по новым заказам и очереди ручной проверки.

## Что делает

| Умение | Команда | Результат |
|---|---|---|
| Разобрать **один** заказ | `python scripts/orders_ops.py order --external-id fl-2411-001` | решение, причина, черновик → `reports/latest-order.md` |
| Проверить связь с ядром | `python scripts/orders_ops.py health` | статус, провайдер, тратит ли деньги |
| Залить заказы в ядро | `python scripts/orders_ops.py ingest` | идемпотентно, без дублей |
| Разобрать пачку заказов | `python scripts/orders_ops.py triage --analyze --only-new` | `reports/latest-triage.md` |
| Очередь проверки | `python scripts/orders_ops.py queue` | что ждёт решения человека |
| Сводка (по расписанию) | `python scripts/orders_ops.py summary` | `reports/daily-summary.md` |
| Сквозные сценарии | `python scripts/orders_ops.py test` | `tests/results.json` |

## Структура

```
AGENTS.md            контракт роли: что делает, чего не делает, формат ответа
IDENTITY.md          имя, роль, тон
SOUL.md              принципы работы (данные прежде мнения)
TOOLS.md             точные команды и интерпретатор
USER.md              о владельце: стек, замер времени, предпочтения
skills/orders-triage/SKILL.md   процедура разбора заказов
scripts/orders_ops.py  мост к API ядра (stdlib, без зависимостей)
data/settings.json     адрес ядра, таймаут, лимиты
data/rules.md          как читать решение ядра
data/profile.json      копия профиля исполнителя (для наглядности)
data/orders-seed.json  5 пробных заказов
tests/messages.json    5 сценариев с ожидаемым результатом
reports/               сюда агент пишет отчёты
```

## Сводка по заказам: когда она нужна

Новые заказы в этой системе появляются только вручную: единственный источник заказов
в ядре — `manual`, парсинг площадок не реализован (ТЗ §22). Поэтому сводка «по расписанию»
не может сообщить ничего нового: пока машина выключена, заказов не возникает, а когда
включена — их приносит человек.

Правильный порядок — в конце рабочей сессии с копилотом, когда ядро уже поднято, а заказы
разобраны:

```bash
python scripts/orders_ops.py summary     # → reports/daily-summary.md
```

Запуск при входе в систему (`Orders Agent Summary (logon)` → `scripts/daily_summary.cmd`)
снят 2026-11-02 по решению владельца: задача вызывала сводку, сводка требует живого ядра,
а ядро при входе никто не поднимает — 0 успешных запусков из 10. Журнал оставлен как
история: `reports/logon-summary.log`, разбор — DEF-021 в репозитории приёмки.

Cron-задача OpenClaw `0 8 * * *` остаётся частью сдачи проекта, но новых данных она
не даёт по той же причине: срабатывает, когда компьютер выключен.

## Как запустить

```bash
# 1) поднять ядро (в его каталоге)
cd "D:/python projects/AI_Freelance_Copilot"
./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8800

# 2) разобрать заказы (в каталоге агента)
cd "D:/python projects/openclaw-orders-agent"
python scripts/orders_ops.py ingest
python scripts/orders_ops.py triage --analyze --only-new
python scripts/orders_ops.py queue
```

Интерпретатор — `python`, не `python3`: на Windows имя `python3` перехватывает заглушка
Microsoft Store и скрипт не выполняется.

## Важно

- Агент **ничего не отправляет** заказчикам: автоотправка откликов в ядре не реализована намеренно
  (ТЗ §22), и агент эту границу не расширяет.
- Агент **не правит данные ядра напрямую** — только через API.
- Решение «на проверку» не отменяется: сомнение системы передаётся человеку как есть.
- Приватность: в репозитории нет ключей и токенов; адрес ядра — локальный (`127.0.0.1`).
