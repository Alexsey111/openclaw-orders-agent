# Orders Triage — разбор входящих заказов

Превращает входящие заказы в одно понятное решение по каждому: **откликаться**, **на проверку**
или **пропустить** — с причиной и, где возможно, готовым черновиком отклика.

Этот файл — процедура. Контракт роли лежит в `AGENTS.md`, команды — в `TOOLS.md`.

## Когда использовать

- владелец принёс один или несколько заказов (текстом, ссылкой, файлом) и спрашивает «стоит ли брать»;
- нужно залить новые заказы в ядро и получить по ним оценку;
- нужно посмотреть, что уже ждёт решения человека;
- пришла задача «собери сводку по заказам» (её ставит автоматизация по входу в систему).

Не использовать, чтобы писать отклики «с нуля» без ядра, оценивать заказы на глаз или
отправлять что-либо заказчику: первое и третье запрещено границами агента, второе — обесценивает работу ядра.

## Входные данные

Обязательно: текст заказа (заголовок + описание) либо `external_id` уже залитого заказа.
Желательно: бюджет, ссылка на заказ, имя заказчика.

Если у заказа нет описания или бюджета — **не досочиняй их**. Заливай как есть: ядро само
помечает такой заказ «на проверку», и это правильный результат, а не ошибка.

## Алгоритм

1. **Проверь ядро.** `python scripts/orders_ops.py health`.
   Если вернулось `{"ok": false, ...}` — остановись и сообщи владельцу, что ядро не отвечает.
   Ничего не выдумывай вместо него.
2. **Зальёшь заказ в ядро** (если его там ещё нет). Готовые пробные заказы:
   `python scripts/orders_ops.py ingest` — идемпотентно, повторные заливки не создают дублей.
   Свой заказ: добавь объект в `data/orders-seed.json` с уникальным `external_id` и повтори ingest.
3. **Запусти разбор.**
   - один заказ: `python scripts/orders_ops.py order --external-id fl-2411-001` — сама находит,
     при необходимости заливает и считает; результат в `reports/latest-order.md`;
   - пачка: `python scripts/orders_ops.py triage --analyze --only-new`
   Флаг `--only-new` разбирает только то, что ещё не разобрано. Без `--analyze` скрипт
   ничего не считает и денег не тратит — только показывает уже готовые решения.
4. **Прочитай решение ядра** из `reports/latest-triage.md` (или из JSON-вывода команды).
   Ключевые поля: `recommendation`, `match_score`, `needs_review`, `review_reason`, `draft_reply`.
5. **Сформулируй ответ** владельцу по формату из `AGENTS.md`. Для каждого заказа:
   решение, причина, что делать человеку.

## Разметка результата для ответа

| Что вернуло ядро | Что писать владельцу |
|---|---|
| `recommendation: apply`, `draft_reply` есть | «Откликаться», показать черновик, предложить отправить самому |
| `recommendation: review` | «На проверку» + причина из `review_reason` дословно |
| `recommendation: skip` | «Пропустить» + чего не хватает: `missing_skills` |
| `match_score: null` | «Оценка не определена» (это не ноль и не 0.00) |
| ошибка API | «Ядро не отвечает» + что именно вернулось |

## Самопроверка

- Все цифры и решения взяты из ответа API, ни одна не придумана?
- У каждого заказа с `needs_review: true` написано, что нужен человек, и названа причина?
- Ничего не отправлено наружу и ничего не записано в ядро в обход API?
- Ответ по-русски и в формате из `AGENTS.md`?

## Ограничения

- Ядро должно быть поднято. Если оно на реальной модели (`is_live: true`), разбор тратит деньги —
  предупреди владельца перед массовым прогоном.
- Скрипт — stdlib-only Python. Никаких внешних библиотек устанавливать не нужно.
- Ссылки на площадки из заказов не открывать: реального сбора заказов в проекте нет (ТЗ ядра §22),
  и агент эту границу не расширяет.
